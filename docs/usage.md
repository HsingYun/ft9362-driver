# 使用指南

## 环境与启动

需要 Linux、支持 flakes 的 Nix，以及 USB `2808:0752` 设备。GUI 还需要桌面显示服务。所有命令从仓库根目录执行：

```sh
nix develop
python tools/capture.py
```

[开发环境](../flake.nix) 提供定制 libfprint、Python、PyGObject 和 GTK 3。它不安装系统服务，也不修改系统认证配置。当前后端旁路匹配，仅用于研究采集。

设备需对当前用户可读写，且未被其他采集程序或服务占用。构建产物附带 udev 规则；需要配置宿主权限时执行：

```sh
nix build
sudo install -m 0644 result/lib/udev/rules.d/60-focaltech0752.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules
```

重新插拔设备后规则生效；内置设备可重启系统。规则使用 `uaccess` 为本地活动会话分配权限，另包含 `plugdev` 组设置。无桌面会话的访问权限需按宿主配置处理。

## GUI

默认启动后连续预览，未开启录制时不写文件。

| 操作 | 行为 |
| --- | --- |
| 暂停 / 恢复预览 | 取消当前采集并关闭设备；恢复时重新打开，保留最后一帧供查看 |
| 录制 | 新建命名手指数据库，或向已有手指数据库追加一个会话 |
| 停止录制 | 提交并结束当前会话，继续预览 |
| 保存当前帧 | 导出完整原始帧、预览 PNG；实时采集还导出序列化的 FpPrint |
| 设备测试 | 释放预览接口后选择分步或综合测试，自动生成报告 |
| 反色 | 仅改变显示和导出的预览 PNG |

预览从偏移 4 读取小端 16 位数据，显示为 40 × 152 灰度图，使用 5–95% 分位对比度拉伸。窗口放大不改变 PNG 的原始尺寸。布局依据见[协议与数据格式](protocol.md)。

等待手指不会自动结束录制。libfprint 报告过热时，工具等待两秒后重试，并保留录制会话。暂停预览或关闭窗口会结束录制；正常关闭会等待待处理操作完成。驱动取消时会收完当前命令的响应再结束，异常情况下需等待该事务超时（OUT 最多 1 秒，图像响应最多 5 秒）；首次打开或通信错误后的采集还会先排空并检查设备状态。

工具显示近期帧率、首末帧间平均帧率和距上一帧的时间。这些是主机接收速率，包含等待和传输时间，不是传感器额定帧率。

## CLI 与离线预览

统一入口为 [capture.py](../tools/capture.py)：

```sh
python tools/capture.py --cli --count 3 --timeout 30 --output build/captures
python tools/capture.py --preview /path/to/frame.bin
python tools/capture.py --help
```

| 参数 | 含义 |
| --- | --- |
| 无模式参数 | 打开 GUI，开始实时预览 |
| `--cli` | 终端采集，默认一帧；每帧保存 `.bin` 和 `.fpprint` |
| `--preview FILE` | 在 GUI 打开完整原始 `.bin`，不访问设备；可反色与导出 |
| `--output DIR` | 输出目录，默认仓库根目录下的 `build/captures/` |
| `--count N` | CLI 采集帧数，正整数，默认 1 |
| `--timeout N` | CLI 每帧等待上限秒数，正整数，默认 30 |

`--cli` 与 `--preview` 互斥。CLI 多帧采集会在帧间提示抬起手指并按 Enter；Ctrl+C 取消当前操作。持续录制由 GUI 提供，CLI 不创建录制数据库。离线预览仍需要 GTK 和 FPrint 类型库，纯数据处理测试不需要。

## 设备测试与报告

点击预览窗口的“设备测试…”。程序结束录制、取消采集，并等待接口关闭后打开测试窗口。测试期间不要同时启动其他硬件工具；窗口关闭后预览保持暂停，由你手动恢复。

### 选择测试范围

| 范围 | 执行方式 | 用途 |
| --- | --- | --- |
| 综合协议验证 | 创建本轮，执行一次，按界面提示完成手指动作；预计 5–10 分钟 | 一次收集信息与生命周期基线、通道对照、接触变化、60 秒连续采集及 50 个取消/恢复组合 |
| 完整复现 | 20 步，每步点击执行，共按压 3 次 | 复现固定动作与 A/B/C/D 通道对照 |
| 仅无手指 / 仅手指动作 / 仅通道对照 | 按所选范围逐步执行 | 单独检查指定行为 |

综合协议验证先要求完全抬手，再提示同一手指保持接触、轻触、正常按压、滚动、抬手和重按，最后再次抬手。查询、采集及各恢复组合自动执行，无需切换用例。该流程会主动取消 USB 传输，并多次复位所选指纹设备；已测范围与未完成项见[设备能力](device-capability.md)。

完整复现的前两次按压用于保持、滚动、抬手和再按；第三次接触持续约 15 秒，自动完成四阶段通道对照。请按提示实际抬手，普通状态 00 不能作为物理离开的判据。

两种流程的模式项都只检查唤醒前提，不发送 `87` 模式写入；不操作固件、未知 EC/GPIO、未知寄存器或整机电源。测试不注册系统指纹。具体实验边界见[开发指南](development.md#综合协议验证)。

### 失败、停止与恢复

| 流程 | 故障处理 |
| --- | --- |
| 分步复现 | Bulk 传输或校验错误暂停流程。可选择“恢复 USB 后重试”或“恢复 USB 后跳过此项”；恢复成功后仍需点击执行 |
| 综合验证的无手指基线 | 失败时保留证据，自动尝试一次 USB 恢复并跳过该项；恢复失败则停止 |
| 综合验证的取消矩阵 | 分别记录被测恢复结果、失败阶段和用例清理结果；清理成功后下一组合独立建立基线。基线、接触前提、清理或接口释放失败则停止，并列出未开始的组合 |

综合验证因故障暂停、轮次状态为“失败”，且已进入取消矩阵并通过报告完整性检查后，可点击“等待恢复并续测剩余组合”。先完全抬手：程序依次关闭接口等待 2、5、15、30 秒，每次等待结束后在同一物理端口重开，检查桥接、应用和尺寸；本恢复阶段不发送 reset、clear-halt 或排空命令。某次检查成功便结束等待，提示先确认抬手、再放上同一根手指，从未执行的组合继续。例如第 20 项失败导致暂停，续测从第 21 项开始，前 20 项及先前采样保持原样；已尝试但失败的项不会自动重测或改成通过。

等待期间可以停止，接口释放失败时立即暂停；四次检查都失败则保留记录，稍后可再次点击续测。2、5、15、30 秒是每次尝试前的独立等待时长，不是设备恢复时限。检查包含重新打开和协议查询，不能把成功归因于“只等待”；USB 自动挂起和重枚举也可能参与。剩余用例仍按各自既定流程建立基线、执行恢复方法和清理。

界面恢复按钮和自动基线恢复均只作用于所选指纹设备，在同一物理端口重开并验证就绪和尺寸。取消矩阵则逐项比较不同恢复方法，具体组合见开发指南。失败记录保留；跳过或取消未命中都不计为通过，流程完成也不表示所有恢复方式有效。

“停止并生成报告”保留已完成证据和未完成状态，但首次运行与续测的处理不同：

| 手动停止的位置 | 保存状态与后续操作 |
| --- | --- |
| 首次运行，包括已进入取消矩阵后 | 轮次记为“已停止”，当前界面不提供续测或作为失败轮次重新打开；需要新建一轮 |
| 已开始的续测，包括等待恢复期间 | 外层轮次记为“失败”，私有记录保存取消或接口释放失败状态；满足报告完整性条件时可再次续测 |

综合验证停止时先请求子进程退出，超过 8 秒仍未退出时终止进程。每次子进程执行最多 20 分钟，首次执行和每次续测分别计时；连续 120 秒无阶段进展也会停止。多次续测的累计轮次时长可以超过 20 分钟。强制终止不保证设备已恢复通信。

“作废本轮并重来”保留旧轮并标记无效，新轮使用独立目录。已有失败轮次可通过“打开失败轮次…”继续处理；已删除或作废的轮次不能恢复。分步重试从失败组的基线重新开始。综合验证的“复位并重做整轮”会独立存档并重跑全部阶段；“等待恢复并续测剩余组合”保留原轮次，仅继续未执行的组合。续测要求版本 2 报告、用例顺序和证据一致、物理端口一致；仅基线或采样阶段失败、旧版本、存在尚未归入索引的用例文件时，不提供续测入口。若 50 项均已尝试但最终检查失败，续测仅进行恢复与最终收尾。

### 报告与原始数据

每轮写入 `build/diagnostics/device-test-<ID>/`：

| 路径 | 内容 |
| --- | --- |
| `report.md`、`summary.json` | 非生物识别摘要：设备信息、状态、长度、时序、计数及验证边界 |
| `private/` | 详细 USB 响应、日志、动作记录和原始图像 |
| `private/validation/` | 综合验证的总索引、基线、各恢复组合和逐帧记录 |

点击“打开报告目录”查看结果。后续分析需要完整轮次目录；公开摘要不足以复核图像和分块数据。报告区分拒绝、阻断、失败、跳过、未执行与取消未命中，不将空 ACK 或状态 09 写成支持。

目录权限为 `0700`，报告与原始文件为 `0600`。阶段及样本保存检查点，停止时保留部分结果；强制终止或断电可能丢失最后一段尚未保存的数据。原始数据不纳入版本控制。已确认的设备行为见[设备能力](device-capability.md)。

## 保存格式

| 文件 | 内容 |
| --- | --- |
| `frame-<UUID>.bin` | 完整的 12,166 字节 USB 原始帧，包含头尾 |
| `frame-<UUID>.fpprint` | libfprint 序列化对象；当前包含同一原始帧，不是特征向量 |
| `frame-<UUID>.png` | GUI 导出的 40 × 152 预览，8 位灰度值以 RGB PNG 存储；不包含协议头尾 |
| `finger-<UUID>.sqlite3` | 一个命名手指的多次录制会话与完整帧 |

SQLite 格式版本为 1：

| 表 | 字段与含义 |
| --- | --- |
| `metadata` | `key`、`value`；含 `schema_version=1`、`finger_name`、`raw_format=FT9362-RAW-v1`、`frame_size=12166`、`timestamp_meaning` |
| `sessions` | `id`、`started_utc`、`ended_utc`；每次新建或追加录制产生一个会话 |
| `frames` | `id`、`session_id`、`received_unix_ns`、`received_monotonic_ns`、`raw`；`raw` 长度固定为 12,166 |

时间戳记录主机收到完整 libfprint 帧的时刻。用同一会话的单调时钟计算帧间隔；不要跨重启或会话拼接。录制约每秒提交一次，正常结束时再次提交；异常退出可能丢失尚未提交的帧，并留下空的 `ended_utc`。

新建输出目录权限为 `0700`，帧文件和数据库为 `0600`；已有目录权限不自动修改。原始数据未加密，默认输出及常见采集文件后缀已在 [.gitignore](../.gitignore) 中排除。将采集数据留在默认目录或仓库外；Git 忽略不等于加密，也不能阻止 `path:.` 形式的 Nix 输入收集它们。

## 故障排查

| 现象 | 检查顺序 |
| --- | --- |
| 没有找到设备 | 确认 USB ID；从本仓库的 `nix develop` 启动；工具要求恰好一台目标设备 |
| 权限拒绝 / 接口忙 | 检查 USB 节点权限、udev 规则，以及其他程序或 fprintd 的占用 |
| 提示旧驱动 | 当前驱动录入阶段数应为 1；退出旧 shell 后重新进入开发环境 |
| FPrint 类型库不可用 | 使用开发环境中的 Python，检查是否覆盖了 `GI_TYPELIB_PATH` |
| 无法连接桌面 | 在桌面终端启动，或使用 `--cli` |
| 等待不出帧 | 完全抬起手指再放上；检查终端错误、冷却状态和设备初始化问题 |
| USB 超时 / 帧长错误 | 保留错误及发生阶段，按[开发指南](development.md)定位；不要通过截断或补零掩盖问题 |
