# 协议与数据格式

目标为 FT9362，USB `2808:0752`。本文汇总当前 Linux 实现与原始帧证据；完整 Windows 命令、初始化和电源流程见 [Windows 移植参考](windows-reference.md)。静态分析结果不等同于本机硬件验证。

2026-10-11 的[本机信息查询实测](device-capability.md)已直接确认设备返回尺寸 40 × 152，以及 HT32 控制器版本身份；查询响应也多出一个尾字节，部分随上一响应同偏移数据变化。加密标志查询仅返回空 ACK，不能据此认定加密关闭。以下旧帧统计与这轮查询证据分别保留。

后续[无手指能力测试](device-capability.md)确认 `81` 在手指状态 00 时也可返回完整图像缓冲，六次载荷相同，包括 USB 设备复位前后。因此取图完成和约 18 ms 的缓冲传输时间不等于新采样完成或额定帧率。心跳可用，应用唤醒返回 09，不能把共享 Windows 初始化命令视为本机全部支持。

再后续的[有手指对照实验](device-capability.md)进一步确认：仅重复 `81` 或附加 `82 73 01` 不刷新；状态为 05 时加入 `82 76 01` 后，后续普通帧持续更新，移除扩展读取后再次固定。普通状态在持续接触期间也会于读图后由 01 变成 00，因此不能把 00 无条件解释为物理抬手；它至少受帧就绪/消费状态影响。

## 当前 USB 通信

[驱动](../driver/focaltech-0752.c)依据上述实机证据实现普通与扩展访问。新的 libfprint 采集流程已通过模拟测试，尚待实机验证；历史诊断结果不代表新驱动已经验收。

| 项目 | 当前值 |
| --- | --- |
| USB 接口 | 0 |
| Bulk OUT / IN | `0x03` / `0x81`，最大包长 64 字节 |
| IN 请求容量 | 剩余接收上限向上对齐到 64；状态首次 64，图像首次 12,224 字节 |
| 每条命令 OUT 超时 | 1,000 ms |
| 单条状态 / 图像响应总超时 | 1,000 / 5,000 ms，从 OUT 完成起计，分块不重置 |
| 扩展状态 06 后轮询间隔 | 50 ms |
| 交给算法的完整普通帧 | 12,166 字节，保持 `FT9362-RAW-v1` 契约 |

| 用途 | 完整命令 | 响应数据与处理 |
| --- | --- | --- |
| 普通就绪查询 | `02 00 03 80 02 01 80` | 01：读取普通图像；00：查询扩展状态 |
| 普通图像读取 | `02 00 01 81 80` | 12,160 字节载荷，完整校验后交给后端 |
| 扩展状态查询 | `02 00 03 82 73 01 f3` | 05：读取扩展图像；06：延时后重新查询普通状态 |
| 扩展图像读取 | `02 00 03 82 76 01 f6` | 完整消费并校验后重新查询普通状态，不交给后端 |

普通 00 不能代表物理抬手，扩展 05/06 也尚未证明是独立接触位。扩展读取后仍检查普通就绪，不直接假定下一帧可用。其他状态值显式报协议错误；不将未知值当作“继续等待”。

命令中的 `81` 与 USB IN 端点地址相同，但二者分别属于协议与 USB 传输层。四条命令在同一个串行状态机中执行，不增加后台采集线程或独立取消对象。

## 响应边界与校验

早期结构推测已由 Windows 主机封包代码及本机响应补充确认：

```text
请求：02 | 内容长度 L（大端 uint16） | 命令及参数 | BCC
响应：02 | 内容长度 L（大端 uint16） | STATUS 和数据 | BCC | 可选包外字节
逻辑长度 = L + 4
BCC = XOR(长度两字节与全部内容)，不含起始 02
```

响应 STATUS=04 表示命令成功，不是手指状态。状态查询的数据长度应为 1，图像应为 12,160。共用接收器按实际传输长度累计，检查起始标记、L 上下界、BCC、设备 STATUS、预期数据长度和包外字节数，再推进状态机。错误响应也检查 BCC；设备拒绝、空 ACK、未知状态、空片段和超量数据均不能变成有效图像。

状态成功响应逻辑长度为 6，接受实收 6 或 7 字节；本机实测为 7。图像逻辑长度为 12,165，本机实收 12,166；协议接收允许零或一个包外字节。普通图像交付后端时另行检查 12,166 字节保存契约，缺少尾字节时报格式不兼容，不补造字节；扩展图像仅用于消费，接受 12,165 或 12,166 字节。包外字节不参与 BCC 或像素解码，普通帧保存时原样保留。

USB 请求容量、实际传输长度和协议逻辑长度各自独立。允许分块返回头部或载荷，但累计不得超过该响应的上限；不接受合并的多条响应，不截断超量数据，也不跨命令拼包。响应未收完整时，在同一个截止时间内继续读取。

单次响应有超时，等待可采集状态的整个动作没有总超时，调用方可取消。取消或错误结束主机动作，但不保证设备端未读应答已清空；当前没有自动 drain、重发、reset 或设备重同步协议。恢复边界与测试说明见[开发指南](development.md)。

## 原始帧布局

以下来自 2026-10-10 一次录制中的 **55 个不同帧**，并结合 2026-10-11 Windows 静态分析。所有偏移从 0 开始，范围包含两端。

| 偏移 | 长度 | 解释与证据 |
| --- | ---: | --- |
| 0 | 1 | 固定 `02`，与 Windows 协议起始标记一致 |
| 1–2 | 2 | `2f 81`，大端值 12,161：状态字节加图像载荷长度 |
| 3 | 1 | `04`，命令成功状态 |
| 4–12163 | 12,160 | 6,080 个小端无符号 16 位采样值，按 40 列、152 行解释 |
| 12164 | 1 | 偏移 1–12163 的 XOR，55/55 帧匹配 |
| 12165 | 1 | 额外尾字节，含义未确认，原样保留 |

```python
import struct
from functools import reduce
from operator import xor

assert len(raw) == 12166
assert raw[:4] == bytes.fromhex("02 2f 81 04")
assert reduce(xor, raw[1:-2], 0) == raw[-2]
pixels = struct.unpack("<6080H", raw[4:-2])
rows = [pixels[y * 40:(y + 1) * 40] for y in range(152)]
```

该示例是对本批响应的离线校验，不是当前驱动的通用解析器。Windows 在运行时尺寸为 40 × 152 时选择专用图像处理，并以无符号 16 位读取采样值；这支持上述解释，不证明所有设备分支均采用同一格式。

图像读取可能按应用信息索引 `07` 的值启用 AES-128-CBC。当前 Linux 与 Python 均不解密。密钥、IV、条件及测试向量保留在 [Windows 参考](windows-reference.md)，不能无条件对所有原始帧解密。

## 图像布局的历史证据

统计基于偏移 4 的原始值，不使用拉伸或反色后的预览。

| 指标 | 结果 |
| --- | ---: |
| 40 列排列：相邻行 Pearson 相关性，逐帧取中位数 | 0.899 |
| 80 列排列：同一指标 | 0.636 |
| 40 列排列：行内相邻值绝对差中位数 | 72 |
| 每 40 个值的换行边界绝对差中位数 | 424 |
| 第 76、77 行间平均绝对差，跨帧取中位数 | 183.2 |
| 其他相邻行平均绝对差中位数 | 171.6 |
| 两个 40 × 76 半幅直接比较的相关性中位数 | 0.048 |

数据支持一张 40 × 152 图像，而非两张重复的 40 × 76 图像。旧的 80 × 76 排列会把相邻两行并列；偏移 6 解码还会漏掉首个采样值，并把尾部字节当作末尾像素。工具已移除这些旧布局。

本批值域为 **64–3,324**。334,400 个采样值中，334,387 个是 4 的倍数；其余 13 个均位于索引 1,677，即零基行 41、列 37。原因未确认，不应丢弃低两位。16 位是存储单位，不能据此认定 ADC 位深。

尾字节有 49 种取值（`03`–`ed`），没有逐帧递增规律，也不是前一校验字节的简单取反。对不同切片尝试的求和、XOR、取反、负和、字求和、Fletcher 与 CRC-8 候选均未匹配全部样本；这不能排除所有私有校验。该字节可能是填充或发送缓冲区残留，但没有确证。

55 帧首末接收时间相隔 **25.616 秒**，54 个间隔对应平均 **2.108 FPS**；间隔中位数 0.372792 秒，最短 0.175377 秒，最长 3.213282 秒。中位数的倒数约 2.682 FPS，不等于平均 FPS。这些是一次主机交付速率测量，不是硬件上限。

## 保存、显示与未知项

[frame.py](../tools/frame.py)将完整帧解码为 40 × 152 预览，采用 5–95% 分位对比度拉伸，可反色；保存的原始字节不变。FpPrint 内部为 `("FT9362-RAW-v1", 字节数组)`，GVariant 类型 `(say)`。该标签标识完整原始帧封装，不是特征模板版本。

`.bin` 和数据库保留完整帧，PNG 仅用于显示。历史分析曾对另行导出的 16 位 PNG 回读验证全部 6,080 个数值一致；当前 GUI 导出的是 8 位预览，不能作为无损数值归档。文件和数据库规范见[使用指南](usage.md)。
