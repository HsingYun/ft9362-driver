# 协议与数据格式

目标为 FT9362，USB `2808:0752`。本文汇总当前 Linux 实现与原始帧证据；完整 Windows 命令、初始化和电源流程见 [Windows 移植参考](windows-reference.md)。静态分析结果不等同于本机硬件验证。

[设备实测](device-capability.md)确认尺寸为 40 × 152，控制器返回 HT32 版本字符串。普通取图可返回固定缓冲；持续接触下，条件扩展取图参与推进普通帧刷新。普通状态 00 不等于物理抬手。加密标志查询为空 ACK，图像是否需要解密仍未确定。

## 当前 USB 通信

[驱动](../driver/focaltech-0752.c)依据上述实机证据实现普通与扩展访问。新的 libfprint 采集流程已通过模拟测试，尚待实机验证；历史诊断结果不代表新驱动已经验收。

| 项目 | 当前值 |
| --- | --- |
| USB 接口 | 0 |
| Bulk OUT / IN | `0x03` / `0x81`，最大包长 64 字节 |
| IN 请求容量 | 剩余接收上限向上对齐到 64；所有响应首次均为 12,224 字节 |
| 每条命令 OUT 超时 | 1,000 ms |
| 单条状态 / 图像响应总超时 | 1,000 / 5,000 ms，从 OUT 完成起计，分块不重置 |
| 扩展状态 06 后轮询间隔 | 50 ms |
| 交给算法的完整普通帧 | 12,166 字节，保持 `FT9362-RAW-v1` 契约 |

| 用途 | 完整命令 | 响应数据与处理 |
| --- | --- | --- |
| 桥接检查 | `02 00 01 34 35` | 要求 `55 AA` |
| 应用检查 | `02 00 03 80 01 02 80` | 要求 `A5 5A` |
| 尺寸 A / B 检查 | `02 00 03 80 03 01 81` / `02 00 03 80 04 01 86` | 分别要求 `28` / `98` |
| 普通就绪查询 | `02 00 03 80 02 01 80` | 扩展状态 05 后查询；01：读取普通图像；00：条件扩展取图 |
| 普通图像读取 | `02 00 01 81 80` | 12,160 字节载荷，完整校验后交给后端 |
| 扩展状态查询 | `02 00 03 82 73 01 f3` | 05：查询普通就绪；06：延时后重新查询扩展状态 |
| 扩展图像读取 | `02 00 03 82 76 01 f6` | 完整消费并校验后重新查询普通状态，不交给后端 |

普通 00 不能代表物理抬手，扩展 05/06 也尚未证明是独立接触位。普通 01 也可能在抬手后出现，所以每次采集先检查扩展状态。扩展读取后仍检查普通就绪，仍为 00 则延时回到扩展状态检查，不直接假定下一帧可用。其他状态值显式报协议错误；不将未知值当作“继续等待”。

命令中的 `81` 与 USB IN 端点地址相同，但二者分别属于协议与 USB 传输层。桥接、应用和尺寸命令用于首次打开或通信错误后的同步检查；采集顺序、命令事务的含义和同步条件见[驱动生命周期](development.md#驱动生命周期)。

## 响应边界与校验

Windows 主机封包代码与本机响应支持以下结构：

```text
请求：02 | 内容长度 L（大端 uint16） | 命令及参数 | BCC
响应：02 | 内容长度 L（大端 uint16） | STATUS 和数据 | BCC | 可选包外字节
逻辑长度 = L + 4
BCC = XOR(长度两字节与全部内容)，不含起始 02
```

响应 STATUS=04 表示命令成功，不是手指状态。状态查询的数据长度应为 1，图像应为 12,160。共用接收器按实际传输长度累计，检查起始标记、L 上下界、BCC、设备 STATUS、预期数据长度和包外字节数，再推进状态机。错误响应也检查 BCC；设备拒绝、空 ACK、未知状态、空片段和超量数据均不能变成有效图像。

状态成功响应逻辑长度为 6，接受实收 6 或 7 字节；本机实测为 7。图像逻辑长度为 12,165，本机实收 12,166；协议接收允许零或一个包外字节。普通图像交付后端时另行检查 12,166 字节保存契约，协议完整但缺少尾字节时，在交付层报格式不支持，不补造字节、不触发设备重同步；扩展图像仅用于消费，接受 12,165 或 12,166 字节。包外字节不参与 BCC 或像素解码，普通帧保存时原样保留。

USB 请求容量、实际传输长度和协议逻辑长度各自独立。允许分块返回头部或载荷，但累计不得超过该响应的上限；不接受合并的多条响应，不截断超量数据，也不跨命令拼包。响应未收完整时，在同一个截止时间内继续读取。

协议没有事务序号，BCC 和长度校验不能证明格式合法的响应属于当前请求。驱动的取消、超时处理与恢复边界见[开发指南](development.md#命令接收与取消)。

## 原始帧布局

以下结合 Windows 静态分析、十指录制的 **757 种不同像素载荷**与 D1、D2 的 **712 条图像响应、640 种内容**。数据集范围及去重方法见[成像报告](imaging-characteristics.md#23-完全重复与统计单位)。所有偏移从 0 开始，范围包含两端。

| 偏移 | 长度 | 解释与证据 |
| --- | ---: | --- |
| 0 | 1 | 固定 `02`，与 Windows 协议起始标记一致 |
| 1–2 | 2 | `2f 81`，大端值 12,161：状态字节加图像载荷长度 |
| 3 | 1 | `04`，命令成功状态 |
| 4–12163 | 12,160 | 6,080 个小端无符号 16 位采样值，按 40 列、152 行解释 |
| 12164 | 1 | 偏移 1–12163 的 XOR，757 个录制帧及 712 条诊断图像响应均匹配 |
| 12165 | 1 | 额外尾字节，含义未确认，原样保留 |

```python
import struct
from functools import reduce
from operator import xor

assert len(raw) == 12166
assert raw[:4] == bytes.fromhex("02 2f 81 04")
assert reduce(xor, raw[1:-2], 0) == raw[-2]
pixels = struct.unpack("<6080H", raw[4:-2])
rows = [pixels[y * 40:(y + 1) * 40] for y in range(152)]
```

该示例是对本批响应的离线校验，不是当前驱动的通用解析器。Windows 在运行时尺寸为 40 × 152 时选择专用图像处理，并以无符号 16 位读取采样值；这支持上述解释，不证明所有设备分支均采用同一格式。

图像读取可能按应用信息索引 `07` 的值启用 AES-128-CBC。当前 Linux 与 Python 均不解密。密钥、IV、条件及测试向量保留在 [Windows 参考](windows-reference.md)，不能无条件对所有原始帧解密。

## 图像布局的样本证据

统计基于 C 的 757 种完整像素载荷，每幅等权；不使用拉伸或反色后的预览。行相关先对每幅图的行对取中位数，再跨图取中位数。其他统计单位在表内说明。

| 指标 | 结果 |
| --- | ---: |
| 40 列排列：相邻行 Pearson 相关性 | 0.896 |
| 80 列排列：同一指标 | 0.633 |
| 40 列排列：所有行内相邻值绝对差的中位数 | 60 |
| 每 40 个值的换行边界绝对差，汇总全部行界取中位数 | 228 |
| 第 76、77 行间平均绝对差，跨图取中位数 | 93.90 |
| 其他相邻行平均绝对差，先逐图取中位数再跨图取中位数 | 93.30 |
| 两个 40 × 76 半幅直接比较的相关性，跨图取中位数 | 0.037 |

数据支持一张 40 × 152 图像，而非两张重复的 40 × 76 图像。按 80 × 76 排列会把相邻两行并列；偏移 6 解码会漏掉首个采样值，并把尾部字节当作末尾像素。完整分位数与局限见[成像布局分析](imaging-characteristics.md#32-行宽与中间边界检查)。

C 的值域为 **880–3,540**。4,602,560 个采样中仅 96 个不是 4 的倍数，均位于索引 1,677，即零基行 41、列 37。该点在不同图像中呈现精确等于四邻域均值与正偏差两种行为；按唯一内容统计的诊断复核见[成像报告](imaging-characteristics.md#42-固定坐标的数值行为)。固件机制未确认，不应丢弃低两位；16 位是存储单位，不能据此认定 ADC 位深。

C 的包外尾字节有 241 种取值，范围 `00`–`ff`，不参与图像去重。尾字节不同不能证明图像更新，也不应当作帧序号或新鲜度证据。现有 BCC 已由明确字段验证；没有证据将额外字节解释为第二种校验。[小包查询的顺序实验](device-capability.md#4-协议封装和额外尾字节)支持部分发送路径存在旧字节残留，但不能直接解释所有图像尾字节。

连续采集的速率按真实事务及时间计算，保留重复读取；图像内容数另行报告。D2 持续阶段 60.135 秒交付 178 个普通帧且载荷均不同，约 2.960 帧/秒，包含人为等待和主机开销，不是设备最大采样率。统计边界与普通／扩展传输耗时见[成像报告](imaging-characteristics.md#73-持续采集接触动作与状态)。

## 保存、显示与未知项

[frame.py](../tools/frame.py)将完整帧解码为 40 × 152 预览，采用 5–95% 分位对比度拉伸，可反色；保存的原始字节不变。FpPrint 内部为 `("FT9362-RAW-v1", 字节数组)`，GVariant 类型 `(say)`。该标签标识完整原始帧封装，不是特征模板版本。

`.bin` 和数据库保留完整帧，PNG 仅用于显示。GUI 导出的是 8 位预览，不能作为无损数值归档。文件和数据库规范见[使用指南](usage.md)。

仍需确认：尾字节语义、固件实际分支、物理像素间距、DPI、方向与镜像、内部校准、固件已执行的图像处理，以及不同启动和电源状态下的返回格式。

原始样本不随仓库提供；公开的[汇总数据](images/imaging/measurements.json)可核对统计值与分母，重新计算像素统计仍需原始输入或独立复测。Windows 二进制证据见[附件](../attachments/README.md)。
